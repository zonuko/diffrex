# Git 統合アーキテクチャ & 意思決定記録 (ADR)

## 1. 背景と課題

Diffrex における Git リポジトリ（ワーキングツリー差分）対応（Phase 7 / B-7）の実装にあたり、以下の課題が発生しました。

1. **Windows におけるコンソールウィンドウの一瞬の点滅 (Command Prompt Flashing)**:
   ファイルツリー内のファイルをクリックして差分を表示する際、裏で `git show HEAD:<file>`（`new Deno.Command("git", ...)`）を実行すると、Windows のコンソールホスト（`conhost.exe`）が一瞬黒い画面（コマンドプロンプト）を描画して即座に閉じる現象が発生する。
2. **ファイルクリック時のプロセス起動オーバーヘッド**:
   ツリー内のファイルをクリックするたびに外部プロセス（`git.exe`）を立ち上げるため、ファイルの切り替えに数百ミリ秒のレイテンシが発生し、エディタの操作感が損なわれる。
3. **外部ツール（`git.exe`）への依存の妥当性**:
   Pure JavaScript/TypeScript の Git 実装（`isomorphic-git` 等）や WASM 版 libgit2 を内包すべきか、それとも既存の CLI ツール同様にネイティブの `git.exe` に依存すべきかの整理。

## 2. 代表的 Diff / IDE ツールの実装調査

主要な差分ツールおよび IDE が「Git のコミット履歴やワーキングツリー差分」をどのように実現しているかを調査しました。

### ① WinMerge / Beyond Compare
- **Git 依存**: 単独では Git リポジトリの構造を解釈しない（**外部ツール専用**）。
- **仕組み**:
  - `git difftool` または `git difftool -d`（ディレクトリ比較）として Git 側から呼び出される。
  - Git 本体（`git.exe`）が、一時ディレクトリ（`%TEMP%`）に「コミット済み（HEAD）のファイルツリー」を展開し、その一時フォルダと作業ツリーのフォルダのパスを WinMerge に引数として渡す。
  - WinMerge 側は「通常のローカルフォルダ同士の比較」として処理する。

### ② VS Code (Built-in Git Extension)
- **Git 依存**: 環境にインストールされた **`git.exe` に依存**（未インストールの場合は警告ダイアログを表示）。
- **仕組み**:
  - Node.js の `child_process.spawn` を使って `git.exe` を実行。
  - プロセス生成時に OS レベルで **`windowsHide: true` (`CREATE_NO_WINDOW` フラグ)** を付与するため、Windows 上でも黒いコンソール画面が一切表示されない。
  - ファイル差分時はディスクに一時ファイルを書き出さず、メモリ上の仮想ドキュメント（`git:/...` URI）として `git show` や `git cat-file --batch` の結果を受け取り、差分エディタに直接流し込む。

### ③ IntelliJ IDEA (JetBrains IDEs)
- **Git 依存**: 環境にインストールされた **`git.exe` に依存**（Settings でパス設定とテスト機能あり）。
- **仕組み**:
  - `GeneralCommandLine` / `OSProcessHandler` を介して `git.exe` を実行。
  - Win32 API レベルで `CREATE_NO_WINDOW (0x08000000)` を確実に指定して起動するため、プロンプトの点滅はゼロ。
  - 差分表示時はディスクに書き出さず、内部の VFS（Virtual File System）上のメモリバッファとして Revision コンテンツを保持し、Diff Viewer に渡す。

## 3. アプローチの比較とトレードオフ

Diffrex において検討された 2 つの主要アプローチの比較です。

| 比較項目 | 方式 1: 一時 Worktree 方式 (採用) | 方式 2: 仮想ドキュメント方式 |
| :--- | :--- | :--- |
| **概要** | 起動時に一時 Worktree（HEAD）を展開し、フォルダ比較エンジンで読む | メモリ上で `git show` を受け取り、エディタに直接渡す |
| **画面点滅の解消** | **完全解消（100%）**<br>ファイルクリック時はプロセス起動ゼロ | **困難**<br>Deno に `windowsHide` がないため Windows で点滅を消しにくい |
| **ファイル表示速度** | **爆速（ローカルファイル読込）** | クリック毎にプロセス起動の待ち時間が発生 |
| **実装・保守コスト** | **非常に低い**<br>既存のディレクトリ比較コードをそのまま流用可能 | **高い**<br>UI 側に「メモリ渡し」の専用分岐ロジックが必要 |
| **起動時間** | 通常リポジトリなら 0.1〜0.3 秒<br>※超巨大リポジトリでは数秒 | 常に一瞬（数ミリ秒） |
| **ディスク消費** | 一時ディレクトリ分を一時的に消費（終了時に自動削除） | 0 バイト |

## 4. 意思決定と選定理由

Diffrex では **「方式 1: 一時 Worktree 方式」** を正式に採用しました。

### 選定理由
1. **Deno の Windows プラットフォーム制約の完全回避**:
   Deno の `Deno.Command` には Windows の子プロセスウィンドウを非表示にする `CREATE_NO_WINDOW` フラグが現状露出していません。一時 Worktree 方式をとることで、ファイルクリック時の `git.exe` 呼び出し自体を完全に無くし、確実に点滅をゼロにできます。
2. **操作レスポンスの最大化**:
   すべてのファイルがローカルファイルとして存在するため、`Deno.readFile` で即座に読み込まれ、ツリー探索時のストレスが皆無になります。
3. **Diffrex 既存アーキテクチャとの自然な親和性**:
   Diffrex の中核である「2つのディレクトリ比較（Base vs Target）」のパイプラインに、一時 Worktree のパスを Base としてそのまま渡すだけで、Diff、シンタックスハイライト、双方向マージ、保存機能がそのまま動作します。
4. **安全なライフサイクル管理**:
   `src/core/git/temp_worktree.ts` により、アプリの正常終了時・異常終了（SIGINT/Unload）時の双方で一時 Worktree（`git worktree remove` / ディレクトリ削除）が自動クリーンアップされます。

## 5. 将来の拡張ロードマップ (巨大リポジトリ対応)

将来的に、数万ファイル以上を含む超巨大リポジトリ（モノレポ等）で「起動時の一時 Worktree チェックアウトに数秒かかる」ことが問題になった場合は、以下の **「差分ファイル限定の一時展開（Sparse/Partial 方式）」** へシームレスに発展させます：

- 全ツリーを展開するのではなく、`git status` で検知された **変更のあったファイルのみ** を一時ディレクトリに `git show HEAD:<file> > temp/<file>` でピンポイント展開する（Git 本体の `git difftool -d` と同等のアプローチ）。
- これにより、10万ファイルの巨大リポジトリであっても、起動時間を 0.1 秒未満に保ちつつ、点滅ゼロ・ローカルファイル高速読み込みのメリットを両立できます。
